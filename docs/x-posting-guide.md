# Xの投稿方法（共有用）

更新日：2026-09-10

SoEmeの投稿担当向けに、本文と画像を準備してXで公開し、結果を確認するまでの手順をまとめます。制作方針・画像プロンプト・過去の操作実績は[既存の制作手順](./soeme-x-creative-workflow.md)を参照してください。

## 1. 本文と画像を準備する

- AI最新情報は公式発表を確認し、本文に出典URLを入れる。発表日や利用条件も確認する。
- 本文は「何ができるか → 具体的な使い道 → 出典」を短くまとめる。
- 投稿画像は緑を基調に統一する。黒・深緑の背景、エメラルド／ライム、白系の文字、署名SoEmeが基本。
- 見出しは短く、主役は大きくする。生成画像は実際に開き、誤字・可読性・本文との一致を確認する。
- 架空のビジュアルは実際の製品画面や性能検証結果として扱わず、必要に応じ「コンセプト画像」と明記する。

## 2. Xで投稿する

1. [X](https://x.com/)を開き、ログイン中のプロフィールとユーザー名が投稿対象であることを確認する。
2. 「ポストする」または投稿作成欄を開く。
3. 完成した本文を入力する。文字数超過やリンクの抜けを投稿画面で確認する。
4. 写真・動画の追加ボタンから、準備したファイルを選択する。
5. 添付のプレビューを確認する。「Preparing media...」などの処理中表示が消えるまで待つ。
6. 本文、画像の順番、添付の取り違え、投稿先を確認し、「ポストする」を押す。
7. プロフィールから新しい投稿を開き、公開された本文と画像を確認する。
8. 投稿のURLを取得し、実際に確認できた結果を記録する。

基本操作の出典：[X公式ヘルプ「ポストする方法」](https://help.x.com/ja/using-x/how-to-post)。ボタン名は表示言語や画面の更新で変わるため、その時点の画面で確認する。

## 3. ブラウザ操作を引き継ぐときの注意

以下は既存の制作手順に記録された直接投稿の操作実績です。2026-09-10に実施したBuffer経由の予約投稿の検証結果は第4節を参照してください。

- 過去に投稿できたのはアプリ内ブラウザ。別のブラウザや別のbotでもログイン済みとは限らない。
- 操作の前後に現在の画面を読み直す。前の画面の要素番号を流用しない。
- ファイル選択イベントを待ち受けてから、実際のファイル入力欄をクリックし、画像を渡す。
- 「Add photos or video」でファイル選択イベントを取得できない場面では、「Choose File／ファイル選択」欄で成功した記録がある。現在の画面で該当する入力欄を確認する。
- 添付の処理完了とプレビューを確認してから送信する。
- エラーやタイムアウトで結果が不明な場合、再送の前にプロフィールを確認する。既に投稿されていれば再送しない。
- 投稿し直した場合も、旧投稿の削除まで完了したとは扱わない。削除は依頼された範囲で行う。

## 4. 予約・毎日の自動投稿の状態

- 添付：緑を基調にしたSoEmeのオリジナル生成画像。「コンセプト画像」と明記し、AI生成の表示を有効化。
- 確認結果：Bufferで送信済み1件を確認し、X上の本文・画像・投稿URLを確認済み。
- ユーザーの指定により、予約の動作確認を兼ねた本番投稿として残す。削除しない。

### 毎日の運用

- 定期実行名：「毎日12時・AI最新情報をXへ投稿」。2026-09-10の設定確認時点で有効。
- 毎日11:30（日本時間）に調査と制作を開始し、Bufferで当日12:00の予約を登録する。
- 開始日は2026-09-10。早朝の初回投稿は別枠とし、本日の12:00は別の未投稿テーマを選ぶ。
- 原則として過去24時間の公式発表を採用。適した情報がなければ直近7日以内の未投稿情報を発表日付きで紹介し、それもなければ見送りを報告する。
- 毎回、画像または短い動画を最低1点添付する。緑を基調に、短い見出しと大きな主役で読みやすく作る。
- 追加課金、有料プラン、有料APIへの切り替えは行わない。
- PC上で調査・制作するため、準備時刻にはPCとCodexを起動しておく。12:00を過ぎて起動した場合は、別時刻に無断変更せず下書きを保存して遅延を報告する。
- 定期実行の有効化と、個々の投稿の予約・公開成功は別々に確認する。本資料の更新時点では、12:00の定期投稿の公開はまだ確認していない。

### Bufferで予約するときの手順

1. Bufferの投稿先が @soeme008zl、タイムゾーンが Asia/Tokyo であることを確認する。
2. 予約一覧と送信済み一覧を確認し、当日12:00の分が既にあれば追加しない。過去と同じ題材・本文の再投稿も避ける。
3. 作成画面に本文と公式出典URLを入力し、画像をアップロードする。プレビュー本文・文字数・添付画像を確認する。
4. 「Set Date and Time」で日付と12:00 PMを指定し、「Done」の後に予約を保存する。
5. 保存後のQueueで、対象日・12:00・Asia/Tokyo・本文・画像が一致することを確認する。
6. 公開後はSentの表示とX上の投稿を確認し、投稿URLを記録する。結果が不明な場合は再送前に一覧を確認する。

今回の操作では、入力欄に文字が見えていてもプレビューと文字数へ反映されない場面があった。ブラウザのPlaywright入力機能（対象入力欄への `fill` など）を使い、プレビューへの反映と保存後の内容を確認して解消した。

また、下書きから予約へ移した際、指定時刻ではなく既定の8:34がQueueに保存された。送信前に同じ投稿を編集し、5:04へ修正して保存・再確認した。作成画面の時刻表示や成功通知だけで予約完了と判断しない。

連携先の切断・未ログイン・投稿先不一致・媒体の添付失敗がある場合は公開せず、必要な対応を報告する。認証情報は共有せず、別のbotや別環境にログイン状態まで引き継がれたと扱わない。

運用時は[Xの自動化ルール](https://help.x.com/en/rules-and-policies/x-automation)および利用サービスの現行条件を確認する。定期投稿の送信はBufferを利用する。

## 5. 投稿後の記録テンプレート

```text
投稿日時（日本時間）：
投稿先（公開ユーザー名）：
投稿URL：
テーマ：
公式出典URL：
使用画像：
公開確認：本文／画像を確認済み、または未確認の理由
```

共有リポジトリには公開してよい情報だけを保存します。パスワード、Cookie、APIキー、トークン、認証画面のURLは記載しません。
