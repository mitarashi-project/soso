# SoEme：緑で統一したAI情報発信とプロフィール画像制作

共有日：2026-09-10

AIニュースを公式情報から選び、投稿文と目を引く画像を制作し、ブラウザでXへの公開まで確認する手順。2026-09-09の実施内容を整理したものです。自動投稿システムが完成したという意味ではありません。

## 実施済みと未完了

- 実施済み：ニュースの調査、オリジナル画像生成、参照画像の編集、ユーザー指示によるXへの即時投稿、プロフィール画像変更、公開後の確認。

- 毎日12時の運用は計画段階。準備用の定期実行は停止中で、BufferとのX連携・予約投稿は未完了。
- 画像生成・編集の利用成功と、特定モデル名やSketch専用機能の搭載確認を区別する。今回の内蔵ツールでは画像モデルを明示的に選択していない。

## デザイン方針

**投稿画像のベースカラーは緑で統一する。**

黒・深緑の背景、エメラルド／ライムグリーンの主役や発光、白系の文字を基本にする。署名はSoEme。青主体の画像は使用しない。

最初は説明の多い3列カード画像を作ったが、ユーザーから「しょぼく見える」「目を惹く画像に」と改善要望があった。以降は次の方針に変更した。

- 1枚目は大きな主役と短い見出し。スマートフォンで一瞬で読める文字量にする。
- ガラス・金属などの質感、光、余白、強い明暗差で視線を集める。
- 題材に合わせて構図を変え、同じカード型の図解を連続させない。
- 詳しい使い方と出典は本文へ。図解が必要なら別画像に分ける。
- 架空の画像を製品の実演・実測結果として見せない。「コンセプト画像」等を明示する。
- いいね数や集客成果を保証せず、公開後の実際の反応で改善する。

## 投稿の制作手順

1. ユーザーのテーマと対象読者を確認する。通常の投稿依頼なら、その範囲で原稿・画像・公開まで進める。
2. 公式発表や公式ヘルプを開き、日付、対象機能、利用条件を確認する。検索スニペットだけで断定しない。
3. 「読者の困りごと → 具体的な使い道 → 指示例 → 必要な確認」の順に短い本文を作る。ニュースの事実と自分の提案・見立てを分ける。
4. 本文に公式出典URLを入れる。文字数はXの投稿欄で最終確認する。日本語やURLには重み付けがあるため、単純な文字列の長さだけで判定しない。
5. 内蔵の画像生成機能で1枚目を作る。修正は元画像を参照し、変更点と維持する要素を明示する。
6. 出力を実際に見て、誤字、見出しの可読性、色、余白、本文との整合性を確認する。
7. Xのログイン先アカウントを画面上で確認する。本文と画像を入れ、添付処理の完了を待って公開する。
8. 成功表示だけでなく、公開された本文・画像・投稿URLを確認して記録する。処理結果が不明な場合は重複防止のため再送前にプロフィールを確認する。

「投稿し直して」という依頼で新規投稿を作成した実例では、旧投稿は削除せず、残っていることを報告した。既存投稿の削除や恒久的な変更は別途その範囲を確認する。

## プロフィール画像の改善手順

既存の緑のキャラクターを参照し、同一性を残して品質を高めた。大きな緑の瞳、明るいライム色の顔、葉の冠、親しみやすい表情を維持し、クリスタルの質感と光を加えた。

```text
参照画像の緑のキャラクターだけを参考に、
Xのプロフィール用の正方形アイコンを制作。
丸い顔、大きなエメラルドの瞳、小さな笑顔、葉の冠を維持。
高品質な3Dキャラクターとして、半透明の葉の結晶、
柔らかな正面光と緑のリムライトを追加。
背景は深緑。顔を大きく中央に配置。
丸く切り抜かれても顔や冠が欠けない余白を取る。
文字・署名・透かし・アプリのUIは入れない。
```

1. Xのプロフィールから「Edit profile」を開く。
2. バナー用とアバター用のアップロード欄を区別して、アバター画像を選ぶ。
3. 切り抜き画面で顔の大きさと収まりを目視し、「Apply」を押す。
4. 「Save」で保存する。
5. プロフィールに戻ったことと、新しい丸いアイコンが表示されたことを確認する。

## ブラウザ操作で分かった点

- UI操作には、その環境で提供されるブラウザ操作機能を使う。古い要素番号を次の画面で流用しない。
- ページ遷移や入力後は状態を読み直す。読み込みで要素が消えた場合は現在の画面から対象を選び直す。
- 画像添付は、ファイル選択イベントを待ち受けてから実際のファイル入力欄をクリックし、ファイルを渡す。
- この環境では「Add photos or video」から選択イベントが取得できない場面があり、実際の「Choose File／ファイル選択」欄で成功した。
- 複数のファイル入力欄があるプロフィール編集では、アバター用を画面上で特定する。
- 投稿画面の「Preparing media...」が消え、添付画像が表示されるまで公開しない。
- 「Apply」は切り抜き適用であり、プロフィール全体の保存とは別。「Save」後の反映まで確認する。

## 毎日12時の投稿について

計画は「日本時間11:30に調査・制作を開始し、12:00の投稿を予約する」。当時は停止中で、接続と最初の予約の検証が残っている。

ブラウザによる都度のユーザー指示投稿と、無人で継続する自動投稿は別の運用として扱う。定期運用を始める前にXの現行ルールと利用する予約サービスの条件を確認し、対応する投稿経路を使う。

Bufferの連携画面では、投稿以外にDMやプロフィール等への広い権限が要求された。その承認は未完了。認証情報や権限を別のbotへ引き継いだと扱わない。ローカル定期処理にはPC・アプリの稼働条件があるため、予約サービス側の実行条件と区別する。
